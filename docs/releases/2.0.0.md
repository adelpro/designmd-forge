# v2.0.0 — sections, brands, palettes, themes, prompts

**2026-11-13** · npm `designmd-forge@2.0.0` · no tool or parameter removed.

## New

- **`designmd_search_sections`** — find `### Footer`, `### Buttons`, `### Navigation` groups _across_ designs. 1,474 groups from 289 designs, synonym-expanded text ("hamburger" also searches menu button, drawer, bottom bar), and prose-derived facets (`has`, `position`). 600 flavour files are excluded and every response says so.
- **Brand dedupe** — `spotify` and `ios-spotify` are one row per group, with both platforms listed. 289 designs collapse to 275 brands.
- **Palette filters** — `designmd_search_designs` gains `mode`, `hue`, `brand`, and accepts an empty query when a filter is present. Coverage is printed: 80 of 301 designs declare tokens; 221 are prose-only.
- **`designmd_list_themes`** — the variants a system actually ships. Astryx's seven, pinned to npm 0.7.15, each with mode, display/body pairing and accent hue. `designmd_get_design_md({ theme })` returns a delta, not a copy of the parent.
- **Four MCP prompts** — `pick-a-design`, `section-inspiration`, `theme-pick`, `author-design-md`. Prompts are user-invoked templates, not skills.
- **Astryx (Meta) reference spec** in _Component Library_, MIT, with an `upstream` block recording the pin.

## Changed

- Multi-word `text` in section search is **AND**, with a stopword list, so "social links" is a search for _social_ rather than for _links_. `"3d hover"` returns 2 genuinely 3D-and-hover buttons, not 47 loose matches.
- `designmd_search_designs` accepts an empty query **when a filter is set**; with neither, it still refuses.
- Palette-filtered responses always print their coverage line.

## Fixed

- `refresh-data` no longer drops authored entries: it now runs every source that stages fragments (`web`, `mobile`, `ios`, `shadcn`, `adelpro`, `astryx`) before `load-data`.
- Unparsable colour values (an `hsl()` triple, a hex with a YAML comment) are treated as absent instead of black — two white systems no longer report `mode: dark`.
- A brand ramp key (`brand-dark-900`) or an `on-dark` contrast pair no longer makes a light system "both".
- The section index no longer loses component groups under an unmapped `##` title, and no longer indexes sub-topics such as `### hierarchy` as components.
- `npm run refresh-data` finish line: `verify-data` (8 offline checks) fails the run if the corpus is truncated.

## Deliberately absent

- Flavour files (SwiftUI / Expo / Android) are not indexed — 600 duplicates would triple every count.
- 221 designs have no declared tokens: no facets, no palette. Prose-regexed palettes would look authoritative and be wrong.
- No mood taxonomy ("minimalist" stays free text), no MCP resources, no invented themes for single-look brands.
